# 加油站综合考核工作台

高速公路加油站综合考核体系（体系A · V2.1 三段加权）的现场打分与排名展示前端。

权重：油品人效 50% ／ 非油增长 20% ／ 二级运营检查 30%。

人效口径 V3（《油品人效考核测算表》）：汽油SGE＝车次×1.0＋升数×0.01，柴油SGE＝车次×1.8＋升数×0.012；
分母统一为实际在岗−4；四段计分：油品45／非油10／人效15／管理30，基准100、封顶120；不设等级，只出排名。

## 目录

- `docs/` — 部署到 GitHub Pages 的静态站点
  - `index.html` 入口
  - `score.html` 现场打分（6 项一票否决 ＋ 73 项运营检查，可离线）
  - `rank.html` 综合排名榜（读取 `docs/data/rank.json`）
  - `calc.html` 人效四步算例
  - `inbox.html` 待交箱（本机登记，防漏交）
- 方案文档、检查表、导入脚本不上传本仓库。

## 离线能力

打分页为 PWA：首次打开后由 Service Worker 缓存全部资源与题目数据，站点无信号时仍可完成打分；提交时生成 Excel 文件，通过微信回传计划经营科汇总。

## 数据流

现场打分 → 生成 `检查表_站名_年月_时间戳.xlsx` → 微信回传 → 科室脚本写入金山文档表格 → AirScript 汇总算分 → 导出 `docs/data/rank.json` → 排名页展示。

## 部署

GitHub Pages，源选 `main` 分支 `/docs` 目录。

### 打分页

- 导出一个 zip：检查表 Excel ＋ photos/ ＋ manifest.json

### 排错（高频场景）
1. **打不开登录页**：确认 `data/items.json` 与 `data/inspectors.json` 存在且为合法 JSON；联网打开一次后 Service Worker 会缓存。
2. **口令不对**：口令区分大小写、无空格；名单在 `data/inspectors.json`，改完刷新页面（缓存版本 `kaohe-v5-0`）。
3. **点提交没反应**：检查每个扣分项是否都填了原因；提交弹层里必须勾「已逐项核对」。
4. **照片没进 zip**：手机浏览器需允许读取相册/相机；单张压缩到长边 1280px，最多 3 张。
5. **分数与定稿对不上**：先确认 SGE 用 56/28（不是 55.65/28.80），会计月天数按实计，毛利用含烟草口径。
6. **照片进金山**：把 zip 交给科室运行 `python tools/read_check_zip.py <zip>`，产出 `wps_upload_queue.json`，再导入金山「考核工作台数据源」；GitHub 不推照片。
7. **换打分人**：改 `data/inspectors.json` → 推 GitHub → 页面强刷一次。
8. **离线**：首次联网打开后自动缓存；断网可打分、可导出，但照片只存本地草稿，联网后再回传。
