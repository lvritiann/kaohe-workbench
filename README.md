## 一、V6 计分口径

| 段 | 项目 | 基准 | 封顶 | 算法 |
|---|---|---|---|---|
| 一 | 油品销量 | 40 | 50 | 40 × 完成率，完成率 ≥125% 封顶 |
| 二 | 非油销量 | 10 | 12 | 销售5 + 毛利5，各封顶6（完成率 ≥120% 封顶） |
| 三 | 油品人效 | 12 | 20 | 人效 ≤49：12×人效÷49；>49：12＋8×(人效−49)÷49 |
| 四 | 现场管理段 | 38 | 38 | 一级考核 5 ＋ 二级运营检查 28 ＋ 神秘访客 5 |

- **综合** ＝ 油品段 ＋ 非油段 ＋ 人效段 ＋ 现场管理段 − 投诉扣分 + 进步加分；基准 100、封顶 120；**不设等级，只出 1–15 名**，同分油品段高者排前。
- **计分方式**：完成多少得多少分，**不打折、不加倍**，到封顶即止（V6 取消了 V5 的「少扣多奖」1.5/0.5 斜率）。
- **人效** ＝ (会计月当量总量 ÷ **已计天数**) ÷ (月均在岗人数 − 4)；当量 SGE ＝ 汽油吨×**39** ＋ 柴油吨×**27**；月均在岗 ＝ 各日在岗之和 ÷ 已计天数；基准 **49**（15 站算术平均 49.26 取整，当年固定、一年一核）。
  - ★ **人效只有一个数源：`docs/data/efficiency.json`（当月实况）**。排名页、计算页、人效看板三处同源同值。
  - ★ **当量口径含批发（2026-11-17 定案 · A 案）**：销量取数范围与销售日报一致，即「现金＋POS＋微信＋支付宝＋工贸卡＋壳牌卡＋**大客户＋定期结算**」。**不做零售/批发拆分**。
    理由：销售日报四品号列本身就是这八项汇总，拆分需另建台账；且考核只认日报这一把尺子。后果已知并接受——省界站（南沙、华山）大客户柴油占比高，人效天然居前，2026-11 有 5 站人效段封顶。
    对照：成品油驾驶舱「零售吨」**不含**大客户/定期结算，所以它与本表的量不可直接比（2026-11 实测差 2–4 倍，全部由批发量解释）。
  - `stations.json` 里的三年平均日均吨是**参考值，不参与计分**——它算出来的是「历史基准人效」，与当月实况不是一回事（2026-11 实测：南沙基准 50.20 / 当月 180.89）。
  - **会计月天数不是常数**：上月 26 日 — 本月 25 日，实际是 **28 / 29 / 30 / 31 天**。
    3 月会计月最短——平年 28 天（2/26–2/28 + 3/1–3/25），闰年 29 天（含 2/29）；其余月份 30 或 31 天。
    ★ 代码里任何地方都不得把天数写死成 30 或 31。浏览器端用 `Engine.accountDays('YYYY-MM')`，Python 端用 `period_of()` / `account_days()`，AirScript 用会计月日期差。
  - 月中滚动用「已计天数」（`period.elapsed`，≤ 该月实际天数），月末自然等于整月天数。
- **SGE 系数来源**：汽油按实测单均 34.75 升/单，一吨 1360 升 ≈ 39 单，一台一份 → 39；柴油按实测单均 153.35 升/单，一吨 1200 升 ≈ 7.82 单，一台顶 3.5 台 → 27.4 取 27。
- **会计月** ＝ 上月 26 日 — 本月 25 日，天数按实计（28/29/30/31）。
- **非油**：销售完成率**不含烟草**，毛利率完成率**含烟草**；毛利率 ＝ 全月毛利额 ÷ 全月销售额，不按日均毛利率平均。
- **一级考核（5 分）**：公司组织的综合检查，每年一次随机抽查，百分制折 5 分。当月未开展记 **NA**，不记 0 分，按 `5 ×（该站其余项得分 ÷ 95）` 折算补齐，榜单标注「一级考核 NA」。
- **二级运营检查（28 分）**：**80 项** 100 分制（依《二级运营检查表8.21.xlsx》），NA 项标准分从分母剔除：`实得 ÷ (100 − NA标准分合计) × 100`，再 × 28%。
- **神秘访客（5 分）**：百分制 × 5%；当月未测按参评站均分填补；**南沙不参与神访**，按同一套 NA 规则折算补齐（不再走 V5 的 ÷85×100）。
- **投诉**：升级 10 分/件、重复 20 分/件、监管转办或媒体曝光 50 分/件，不设下限；重大投诉触发一票否决。
- **进步加分**：年度人效同比每升 1% 加 0.2 分，上限 3 分，不参与月度排名。
- **一票否决 6 项**（依《二级运营检查表8.21.xlsx》）：**经营证照、核心检测报告、人员资格证件、合规备案文件、散装汽油销售管控、危险废物管理**。触发即当期综合得分 0、排名垫底、当年不得评优。
  - 与旧版的差异：原「资质证照办理」拆成「经营证照 / 人员资格证件 / 合规备案文件」三项；删掉「油品质量合规」（并入常规项 37/39/40）与「重大投诉」（不再进检查表否决清单，仍按 `complaint.major` 规则单独处置）。
- **玉华宫**按定稿附录B：月均在岗 12 人 → 分母 8 → 人效 50.67 → 人效段 12.27。

## 二、页面

| 页面 | 用途 |
|---|---|
| `index.html` | 首页、四项分值、运营状态摘要、全部入口 |
| `score.html` | 现场打分：6 项否决 + 80 项判定，默认满分反向打分，支持照片 |

手机端优先，支持日间/暗色主题；Service Worker 离线缓存，站点无信号也能打分。

## 八、排错（高频场景）

1. **打不开登录页**：确认 `data/items.json`、`data/inspectors.json` 存在且为合法 JSON；联网打开一次让 SW 缓存。
2. **口令不对**：手机号**后四位、含前导零**（`0045` 不能输成 `45`）、无空格；名单改过要联网打开一次并强刷（`/data/` 网络优先）。
3. **点提交没反应**：每个扣分项必须填原因；提交弹层必须勾「已逐项核对」。
4. **照片没进 zip**：手机需允许相册/相机权限；单张**硬压到 ≤500KB**（长边 1600px，质量从 0.82 逐档降到 0.5，还超就缩边重试，最多 4 轮），每项最多 3 张。缩略图上会显示「已压缩 xxxKB」，拍完就能确认有没有超。
   - 照片总量超过 **30MB** 会拒绝打包并提示（安卓上 `JSZip` 造太大的 blob 会 OOM）。真要导出可以点「仍然导出」，风险自负。
   - 压不下来时（超大原图 / canvas 有尺寸上限）会提示「图片已压缩到最大程度」，不会静默出空图。
5. **分数与定稿对不上**：确认用 39/27（不是 55.65/28.80、也不是 V5 的 56/28）、基准 49（不是 65）、月均在岗−4、**会计月实际天数 28/29/30/31**（不是写死 30，月中用已计天数）、毛利含烟草、分母不是当日人数。
6. **排名页的人效和看板不一样**：只可能是一个原因 —— 有人把 `build_rank.py` 的 `eff_map` 改回读 `stations.json`。人效段**只能**读 `docs/data/efficiency.json`（当月实况）；`stations.json` 是三年日均参考值，不参与计分。改完跑 `python tools/build_rank.py`，15 站的 effScore 必须与 `efficiency.json` 逐站相等。
7. **人效看板不刷新**：AirScript 末尾的 `main();` 不能删；看 `efficiency.json` 的 `updatedAt`；SW 对 `/data/` 是「先网络后缓存」，断网才用旧值。
8. **照片进金山**：`python tools/read_check_zip.py <zip>` 一次产出三件 —— `检查明细_导入行.tsv`（粘贴）、`kdocs_upload_payload.json`（base64 直传清单）、`wps_upload_queue.json`（回填 attachmentId）。照片只进金山在线表，GitHub 零照片；在线表需先扩「照片文件名 / 照片附件ID」两列。
9. **换打分人 / 改题目**：改对应 JSON → 推 GitHub → 升 sw 版本 → 页面强刷。
10. **离线**：首次联网打开后自动缓存；断网可打分可导出，照片只存本地草稿。

10b. **点提交后没下载到文件 / 弹出「未安装可打开该链接的应用」**：那条提示是**手机系统**弹的，不是本页弹的——微信／企微／QQ 的 X5 内核会把 `blob:` 当超链接交给系统 Intent，系统里没有能开 `application/zip` 的应用。
    - 正常路径是**系统分享面板**：点提交 → 选微信 → 发给计划经营科。**不需要下载**。
    - 若弹出的是「这个浏览器存不了文件」，说明你在内置浏览器里，点右上角 `···` → **在浏览器打开**，草稿会保留。
    - 若走的是下载分支，文件在手机「下载」或「文件管理」里，**草稿会保留**（下载是否落盘浏览器不回话，不能拿草稿去赌）；找不到就点面板里的「重新导出」，它复用内存里已打好的包，不会重新压一遍。
    - 取消分享不算失败：草稿保留，面板上有「重新分享」可直接重发。
11. **停业站仍出现在榜上**：检查 `station_status.json` 的 `from`/`active` 与 `status.html` 签发的变更单是否已推送。
12. **`git push` 卡住 / SIGTERM**：代理环境下 HTTP/2 大包会挂起。改用「显式令牌 + HTTP/1.1」（令牌只从 `.gh_token.txt` 读，不写入 git 配置）：
    `python -c "import subprocess;t=open('.gh_token.txt',encoding='utf-8').read().strip();subprocess.run(['git','-c','http.version=HTTP/1.1','-c','http.postBuffer=5242880','push','https://x-access-token:'+t+'@github.com/lvritiann/kaohe-workbench.git','main'])"`
    验证：看 GitHub 仓库最新提交 SHA 是否等于本地 `git rev-parse --short HEAD`。若 `git ls-remote` 报 `schannel: server closed abruptly`，只是网络抖动，用 API 查 `branches/main` 确认即可，不要盲目重推。
13. **登录慢 / 提交时提示「离线组件未就绪」**：登录页已改为只等名单，不再同步加载 862KB Excel + 96KB Zip 组件。若仍慢，多半是 Service Worker 旧缓存 —— 确认 `sw.js` 版本为 `kaohe-v6-7` 后强刷一次。导出组件在登录后后台加载；首次提交若未就绪会弹提示，联网打开一次即可，已填内容存在本机草稿不会丢。

14. **`git push` 被拒（non-fast-forward）**：AirScript 每次运行都会直接向 GitHub 推 `docs/data/efficiency.json`，远端因此多出本地没有的提交。**千万不要 `--force`**，会丢掉实时人效数据。按第 12 条的显式令牌写法先 `git fetch <仓库地址> main`，再 `git rebase FETCH_HEAD`，最后重推。验证：线上 `efficiency.json` 的 `updatedAt` 没有回退成旧值。

15. **扣分落不进记录表 / 落了但分数不对**：三条必查，全部已修，见第十二章。
    - 站名对了、月份对了，但记录表里那一块还是空的 → 检查 `record_sync.py` 的块起点是**探测出来的**还是写死的。年度表 79 行/块、新版 78 行/块，写死任何一个都会从第 2 站起逐站错位。
    - 折算分比打分页显示的高 → 「检查明细」里少了扣分项。**没照片的扣分项也必须有一行**，否则 `record_sync` 找不到该项就按「符合」给满分。
    - 26–31 日打的检查落到上个月 → 打分页「会计月」默认值没跟着 26 日滚动。现场检查正好排在这个窗口，务必确认页面默认值等于当前会计月。

16. **记录表里某站运营段空着**：先分清两种情况。
    - 那个站**根本没去检查** → 空着是对的，`record_sync` 会打印「未检查（留空，不给分）」清单。
    - 那个站**检查了、零扣分** → 应该有 100 折算 / 28 运营段。若空着，说明「检查明细」里没有该站该月的行；正常流程下 `read_check_zip.py` 会自动补一条序号为空的占位行。看它的输出里有没有 `[INFO] … 生成 1 条占位行`。
17. **`record_sync` 打印 `[ERROR] … 块标题探测到 N 块，期望 30 块，本表不动`**：这是保护，不是故障。记录表 A 列的块标题（含「二级运营检查记录」）被改动或删掉了。修回模板再跑——它宁可这次不落表，也不会把扣分写错人。
18. **`record_sync` 打印 `[WARN] 序号在记录表里找不到对应行`**：明细里的序号不是 1–80。常见于手工录数时把序号写成 81/99，或把否决项当成普通项录。这些扣分**没有落表**，必须改明细重跑。
19. **`record_sync` 打印 `[ERROR] … 「表类型」都不在白名单内`**：明细「表类型」列填了「神秘访客」之类。能填的只有「运营检查」「二级运营检查」或留空。注意这条和「检查明细暂无数据，跳过」是两回事——前者是填错了，后者是真的没人填。
20. **`record_sync` 打印 `[WARN] 站块的标准分合计 = x（应为 100）`**：记录表模板被改坏（漏行/多行/改分）。折算分仍按块内合计算，但请先把模板修回来。

### 五条铁律（2026-11-18 修复，勿回退）

1. **一行一个扣分项，不是一行一张照片。** 照片是可选的，扣分项是必记的。若按有照片的项出行，无照片的扣分项就会缺席；`record_sync` 找不到该项 → 按「符合」给满分，等于白扣。现由 `manifest.deductions` 提供权威清单，`read_check_zip.py` 旧包降级时会给 WARN。
2. **「检查了、零扣分」必须留痕。** `deductions` 为空是正常业务结果（一个站查下来没挑出毛病），不是空包。`read_check_zip.py` 会补一条**序号为空的占位行**，`record_sync` 靠「明细里有没有这个站这个月」区分「满分」与「未检查」——前者写 100 / 28，后者整块留空。**判据是 `meta` 里有没有 `(站名, 会计月)`，不是有没有扣分项。**
3. **块步长必须探测，探测失败必须拒绝写入。** 版式有四种组合（旧 78/79、新 85/86），写死任何一个都会从第 2 站起逐站错位。`_block_starts()` 探测到的块数 ≠ 30 时 `main()` 直接 `return`，一格都不写——宁可这次不落表，也不能把 A 站的扣分写进 B 站。项数同理：`_block_layout()` 逐块按「合计」行定位，不假定 73 或 80。
4. **未检查 ≠ 满分。** 本月无任何明细行的站，整块保持模板原样，并打印「未检查（留空，不给分）」清单。
5. **明细的「月份」「表类型」「序号」都要校验。** 月份已自动归一（`2026-11` / 日期时间 / `2026/11` / `202611` 都认）；`表类型` 只接受空或「运营检查」，神访等混入的行会被丢弃并告警；序号找不到对应项的扣分行会列进「扣分已丢失」告警，不再静默按满分处理。

### 折算口径（与 `docs/assets/engine.js` 的 `inspectResult()` 逐位对齐）

```
effective = 100 − NA 项标准分之和          ← NA 项不进分母，也不进得分
converted = 实得分 ÷ effective × 100
运营段    = converted ÷ 100 × 28，封顶 28
一票否决  → 当期综合记 0（否决项序号 'v3'，不进分母、不参与 80 项计分）
```

各项得分的判法（`_fill_block`）：

| 明细结果 | 得分列 | 落表 |
|---|---|---|
| `NA` | 任意 | 得分写 `NA`，该项标准分不进分母 |
| `符合` / `合格` | 空或 = 标准分 | 得标准分 |
| `扣分` / 空 | 空 | 全扣，得 0 |
| `扣分` | 0 < 得分 < 标准分 | 按填写的部分得分采信，并计入「结果与得分不一致」告警 |
| `扣分` | 得分 ≥ 标准分 | 按扣分记 0，并计入「结果与得分矛盾」告警 |
| 明细里没有该项 | — | 视为符合，得标准分 |

照片文件名 / 照片附件ID 会从「检查明细」带进记录表的 H / I 列，方便打印留档。

### ★ 上表操作硬性步骤（错了就白丢 28 分）

粘 `检查明细_导入行.tsv` 时，**那条「序号」为空、「检查项目」写「本次未发现不符合项」的占位行必须一起粘进去**。

它代表「这个站检查过了、零扣分」。如果按「序号为空」把它过滤掉：
`record_sync` 在明细里就找不到这个站这个月 → 判定为「未检查」→ 整块留空 → 该站**白丢运营段 28 分**。
**代码补不上这一层**，只能靠操作纪律。
