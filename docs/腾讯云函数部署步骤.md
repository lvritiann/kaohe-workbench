# 腾讯云函数中转 · 部署步骤

> 目标：让检查人手机**零配置**提交，照片直接落进金山「检查明细」。
> 全程网页操作，不用命令行。约 10 分钟（含实名认证）。
>
> 为什么不用 GitHub 中转：GitHub 的触发接口载荷上限 65,535 字符，
> 而一次检查的照片 base64 约 6,700,000 字符，差 100 倍，传不进去。

## 第 0 步 · 登录与实名

1. 打开 <https://console.cloud.tencent.com/scf>
2. 微信扫码登录（有 QQ 账号也行）
3. 首次使用会要求**实名认证** → 选「微信扫码认证」，按提示刷脸，约 1 分钟

> 实名是腾讯云的硬要求，跳过不了。不做实名，函数创建按钮是灰的。

## 第 1 步 · 新建函数

> ⚠️ **会弹一个「个人标准版 12 元/月」的购买窗 —— 直接关掉，不用买。**
> 我们的用量一年不到 1 元，买了纯浪费。详见文末「费用」章节。

左侧菜单 **函数服务 → 函数管理** → 点 **新建**

按下表填，其余保持默认：

| 项 | 填什么 |
|---|---|
| 创建方式 | **从头开始** |
| 函数类型 | 事件函数 |
| 函数名称 | `kaohe-relay` |
| 地域 | **广州**（或上海，选一个就行，之后不要换） |
| 运行环境 | **Node.js 24.11** |
| 函数代码 | **空白函数** |

### 运行环境为什么选 24.11

下拉里可能给四个：`24.11` / `22.11` / `20.19` / `18.15`。选 **24.11**。

| 版本 | 状态（Node.js 官方发布表） | 能不能选 |
|---|---|---|
| **24.11** | **LTS，维护到 2028-04** | ✅ 选它 |
| 22.11 | LTS，维护到 2027-04 | 🔸也行，比 24 早一年到期 |
| 20.19 | **2026-03-24 已 EOL** | ❌ 别选 |
| 18.15 | **2025-03-27 已 EOL** | ❌ 别选 |

18 和 20 都过了生命周期，腾讯云迟早下架，用到那时会强制你迁移——
现在省一秒，以后要重新部署一遍。24 和 22 都是 LTS，但 24 的维护期多一年。

我们这份代码只用了 `https` / `http` / `url` / `Buffer` / `async-await`，
这四个版本全都支持，所以选新版本**没有任何兼容风险**。

填完点 **下一步 / 完成**，进入函数详情页。

## 第 2 步 · 上传代码

**推荐走「上传 zip」**，不要在线粘贴。原因是 Cloud Studio 在浏览器里会拦截剪贴板，
粘贴可能静默失败 —— 编辑器里还是旧模板，部署上去就报
`0 code exit unexpected`（状态码 443 UserCodeError），而且看不出任何线索。

### 方式 A：上传 zip（推荐）

1. 函数管理页 →「函数代码」区块
2. **提交方法** 选 **本地上传zip包**
3. 点「选择文件」，选 **`dist/kaohe-relay.zip`**
   （没有这个文件就跑一次 `python tools/relay/build_zip.py` 生成）
4. 上传 → 保存
5. 确认「执行方法」显示 `index.main_handler`

上传是**整包替换**：原来的 `index.mjs` 会被一起清掉，包里只有一个
CommonJS 的 `index.js`。这正是我们要的干净状态。

### 方式 B：在线编辑（备用）

如果「本地上传zip包」是灰的选不了：

1. 点文件树里的 `index.mjs`
2. **Ctrl+A 全选 → 删除**，一个字都不留
3. 粘贴 `tools/relay/scf.mjs` 的**全部内容** —— 注意是 `.mjs` 那一份
4. 确认第一行是 `import https from 'node:https';`（不是就别往下走）
5. 点 **部署**

### ★ `.mjs` 和 `.js` 不能混

| 文件名 | 该贴哪份 | 用错会报 |
|---|---|---|
| `index.mjs` | `scf.mjs`（ES 模块，`import` / `export`） | `exports is not defined` |
| `index.js` | `scf.js`（CommonJS，`require` / `exports`） | `Cannot use 'import' outside a module` |

一句话记法：**看后缀，`.mjs` 贴 `scf.mjs`，`.js` 贴 `scf.js`。**

> 粘贴后请在浏览器弹「是否允许粘贴」时**点允许**。Cloud Studio 首次粘贴会被拦，
> 拦了就什么都不发生 —— 这是昨晚那次失败的根源。

改完没有报错，再往下走第 3 步。

## 第 3 步 · 填环境变量与超时

切到 **函数配置** 标签 → 点 **编辑**

### 3.1 环境变量（两条，名字一字不能差）

| 变量名 | 值 |
|---|---|
| `KDOCS_URL` | `https://www.kdocs.cn/api/v3/ide/file/85jEfN5x3rM95XxYSTpi1xHALnB45UGde/script/V2-17pmGRi9vJcYHgSkcQZsnX/sync_task` |
| `KDOCS_TOKEN` | 你的 AirScript 脚本令牌（见下方「令牌在哪」） |

可选两条（不填就用默认值，一般不用动）：

| 变量名 | 默认 | 说明 |
|---|---|---|
| `TIMEOUT_SEC` | `20` | 单次 HTTP 请求超时（秒）。中转是「提交 + 轮询」，单次要短 |
| `ASYNC_POLL_SEC` | `0`（自动） | 轮询上限（秒）。**填 0 = 自动**：按函数剩余执行时间 − 5 秒算，你把函数超时从 60 改到 120 / 300 都不用动这里。填正数则封顶 |

### 3.2 其他配置

| 项 | 改成 |
|---|---|
| 执行超时时间 | **120 秒**（默认 3 秒）。照片多、`Range.InsertImage` 慢的时候 60 秒会等不完；SCF 允许 1~900 秒 |
| 内存 | 128MB（默认值即可） |

> 为什么是 120 秒而不是更大：手机端等待上限是 **150 秒**（`docs/assets/score.js` 的
> `CLIENT_WAIT_MS`）。函数给 120、客户端给 150，中间留 30 秒网络余量，不会出现
> 「服务端刚要回包、页面先掐断」。要再往上加，**两边必须一起改**，
> 否则函数等得比页面久，等于白等。

改完点 **保存**。

> **令牌在哪**：金山文档打开「考核工作台数据源（V2.1）.xlsx」→ 效率 → 高级开发 →
> AirScript 脚本编辑器 → 工具栏「脚本令牌」。这个令牌是账号级的，**只填在这里，不要贴到任何网页上**。

## 第 4 步 · 启用「函数 URL」（不是触发器）

> ★ **不要建触发器。** 腾讯云的 API 网关产品已于 2025-06-30 停止服务，
> 2024-07-01 起就不允许新建 API 网关触发器了。控制台里那一排提示说的就是这个。
> 替代品就是「函数 URL」—— 功能一样，还更简单：不用建 API 服务、不用调网关超时。

在函数详情页，点左侧菜单的 **函数 URL** → 点 **新建函数 URL**：

| 配置项 | 选什么 |
|---|---|
| 别名 / 版本 | **`$LATEST`**（别选具体版本号，否则改了代码不生效） |
| 公网访问 | **开启** |
| 内网访问 | 关闭（用不到） |
| **CORS** | **保持关闭** ← 见下方说明 |
| **授权类型** | **开放**（不是 CAM 鉴权，否则手机调不动） |

点确定。页面上会出现一个地址，长这样：

```
https://1258344699-xxxxxxxx.sh.tencentscf.com
```

中间 `sh` 是上海地域（广州是 `gz`）。**把这个地址复制下来。**

### 为什么 CORS 要关着

我们的函数**自己会返回跨域头**（`Access-Control-Allow-Origin` 等）。
如果函数 URL 那边再开一次 CORS，浏览器会收到两套互相打架的头，
报 `The 'Access-Control-Allow-Origin' header contains multiple values`
—— 比没有头还难查。

先关着。只有一种情况才回头开它：手机端报跨域错误且确认不是本函数的问题。
真到那一步告诉我，我把函数里的跨域头去掉，两边只留一处。

### API 网关那一套为什么作废了

| 原来要做的 | 现在 |
|---|---|
| 建 API 网关触发器 | 启用函数 URL |
| 勾「集成响应」（否则跨域头被吞） | 不需要，函数 URL 默认透传 |
| 去 API 网关控制台把超时 15 秒改 60 秒 | **不需要**，函数 URL 直接用函数自身的超时（第 3 步已设 60 秒） |

也就是说，少了一个控制台、少一个坑。

## 第 5 步 · 自测

浏览器直接打开第 4 步拿到的地址（GET 请求）。正常应返回：

```json
{"ok":true,"service":"kaohe-scf-relay","version":"2.0-async","hasTarget":true,"hasToken":true,"pollSec":115}
```

`runtime` 是不是 `v24.x` 无所谓，它只是告诉你函数跑在哪个 Node 版本上，方便排查。
**但 `version` 必须是 `2.0-async`** —— 看不到这个字段，说明函数还是 1.x 的老包，需要按第 2 步重新上传 zip。

四个字段必须都对：

| 字段 | 含义 | 不对怎么办 |
|---|---|---|
| `ok: true` | 函数跑起来了 | 502 → 执行方法不是 `index.main_handler` |
| `version: "2.0-async"` | 已是「异步提交 + 轮询」版 | 没有这个字段 → 还是老包，重新上传 zip |
| `hasTarget: true` | 读到了 KDOCS_URL | false → 环境变量名拼错或没保存 |
| `hasToken: true` | 读到了令牌 | false → 同上，改完要重新保存 |

## ★ 为什么改成了「异步提交 + 轮询」（2026-11-20）

现场出现过这个报错，但**金山表里其实已经写进去了**：

```json
{"errno":10000,"msg":"","reason":"","result":"Unavailable"}
```

WPS 官方社区的定性：`sync_task` 是**同步**接口，脚本一重（写多行明细 + `Range.InsertImage` 嵌照片）
就会返回 `errno:10000 / "Unavailable"`，**而脚本本身是执行成功的** —— 于是出现
「表里有数据、页面报没能落表」这种最误导人的状态，现场的人一看红字就会再交一遍。

所以中转改成官方推荐的异步方式：

```
① POST {script}/task                → 毫秒级拿到 task_id
② GET /api/v3/script/task?task_id=  → 每 0.7~3 秒轮询，直到 status=finished
③ 把最终结果原样回给页面（信封形状与 sync_task 一致，前端解析代码不用改）
```

配套三处兜底：

| 情况 | 行为 |
|---|---|
| 异步接口不可用（老账号 / 接口变更） | 自动退回 `sync_task`，行为与旧版一致 |
| 轮询把预算用完（函数 120 秒时约 115 秒） | 返回 `pending:true`，页面显示**「已提交 · 结果未确认」**（不是红色失败），并引导去核对 |
| 函数返回仍是 `errno:10000 / Unavailable` | 前端也认得这个特征，同样按「未确认」处理 |

**关键认知**：`Unavailable` 不等于失败，`pending` 也不等于失败。
两种情况页面都**不会清掉本机草稿**，所以真没落表的话回来点一下就重交了；
而脚本本身就是「同站同月整体替换」，重复提交不会产生第二行。

自测通过后，**把这个地址发给我**，我填进 `docs/assets/config.js` 并部署，
之后所有手机打开打分页就能直接提交，不用配任何东西。

## 常见错误对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 任何请求都返回 `{"errorMessage":"0 code exit unexpected","statusCode":443}` | 代码没加载起来（443 = UserCodeError）。绝大多数是浏览器拦截了粘贴，编辑器里还是旧模板 | 改用第 2 步「方式 A」上传 zip，一次解决 |
| 触发器弹窗里「触发方式」只有「定时触发」 | 你走的是触发器这条路 | 见第 4 步：不要建触发器，改用「函数 URL」 |
| `ReferenceError: exports is not defined` / `require is not defined` | 把 CommonJS 版贴进了 `index.mjs` | 换成 `tools/relay/scf.mjs` 重贴（见第 2 步） |
| `SyntaxError: Cannot use 'import' outside a module` | 反过来，把 ES 模块版贴进了 `index.js` | 换成 `tools/relay/scf.js` 重贴 |
| 页面显示 `{"errorCode":1,"errorMessage":"Content length[xxx] exceed sync content length [6291456]"}` | 照片太多，超了函数 6MB 硬限制 | 删掉几张照片再提交（前端已卡 5MB，一般不会走到这） |
| 调用很慢后报超时 | 函数超时还是默认 3 秒 | 回第 3 步改成 60 秒，改完重新部署 |
| 手机端报跨域 / 连不上 | 多数是函数 URL 的授权类型选了 CAM 鉴权 | 改成「开放」；仍不行再排查 CORS |
| 页面一直返回旧代码的结果 | 函数 URL 绑在了某个具体版本上，没跟 `$LATEST` | 删掉重建，别名/版本选 `$LATEST` |
| `hasToken: false` | 环境变量没保存，或保存后没重新部署 | 改完环境变量要再点一次「部署」 |
| 返回 `没有收到参数（Context.argv 为空）` | 请求体没传对 | 说明链路通了、令牌也对，是前端 payload 的问题，把这段发我 |

## 费用

### 先说结论：不用买任何套餐，一年花不到 1 元

控制台上会弹一个「**个人标准版 12 元/月**」的套餐窗口。**不用买，直接关掉往下走。**

那个套餐包 100 万次调用 / 10 万 GBs 资源，是给有正式业务量的人准备的。
我们一个月撑死 15 次调用，连它的 0.002% 都用不到，买了纯浪费。

### 那 3 个月试用到期后会停吗？

不会停，也不会强制你买套餐。腾讯云官方计费文档原文：

> 开通使用云函数三个月后的用户每月**不再享受免费试用额度，采用按量计费模式**。

意思是：前 3 个月有免费额度兜着，第 4 个月起**按实际用量扣钱**。
只要账号里有钱（或者你充个 10 元放着），服务照常跑，不会有任何中断。

### 我们实际会用多少

按最坏情况估：15 站，每站每月提交一次，每次带 5MB 照片。

| 计费项 | 单价 | 我们的用量 | 月成本 |
|---|---|---|---|
| 函数调用次数 | 0.0133 元/万次 | 15 次 | ≈ 0.00002 元 |
| 资源使用量 | 0.00011 元/GBs | 0.5 秒 × 128MB × 15 次 | ≈ 0.0001 元 |
| 公网出流量 | 0.8 元/GB | 15 × 5MB ≈ 75MB | ≈ 0.06 元 |
| **合计** | | | **≈ 0.06 元/月** |

**一年不到 1 元。** 充 10 元能用十几年。

### 唯一需要留意的

流量那一项没有独立的免费额度兜很久，按量走，也就是上面那 0.06 元/月；
不在意的话什么都不用做。

想彻底心里有底，可以在腾讯云控制台「费用中心 → 可用额度预警」里设一个
1 元的告警阈值，超了会发短信，不会闷声扣钱。
