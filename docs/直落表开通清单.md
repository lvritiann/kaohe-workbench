# 打分直落金山表 · 开通清单

一次性配置，配好之后**检查人**在手机上打分、拍照、点提交，扣分项和佐证照片直接进「检查明细」，
不需要打包、不需要下载、不需要发微信、也不需要开电脑。

> 角色分清：被打分的是油站，**打分并提交的是检查人**（计划经营科派出的考核人员，十余人）。
> 站长不参与提交，只在结果发布后确认得分。

---

## 你要在金山里做的 3 件事

### 1. 粘贴脚本

打开 **考核工作台数据源（V2.1）.xlsx** → 顶部「效率」→「高级开发」→「AirScript 脚本编辑器」→ 新建脚本
→ 把 `tools/airscript/score_write.js` 整个贴进去 → 保存（脚本名建议叫「打分直落表」）。

> 注意是 **AirScript 脚本编辑器（JS）**，不是右边的「PY 脚本」。
> `record_sync.py` 走 PY，这个走 JS，两个不是一处。

### 2. 建脚本令牌

同一个编辑器里，工具栏点「脚本令牌」→ 创建 → 复制那串字符。
（没做过实名认证会先让你认证一次。）

### 3. 复制 webhook 链接

脚本列表里找到刚存的「打分直落表」→ 右侧 `···` → 复制 webhook 链接。
长这样：

```
https://www.kdocs.cn/api/v3/ide/file/85jEfN5x.../script/V2-xxxx/sync_task
```

## 要不要每次都去点「运行」？不用

AirScript 脚本有三种跑法，这里只用第一种：

| 跑法 | 谁触发 | 用在哪 |
|---|---|---|
| **webhook（本方案用的）** | 手机点「确认提交」那一刻自动 POST | 打分直落表 |
| 定时任务 | 金山云端按你设的时间跑，不用开机、不用打开表格 | 每月把「检查明细」汇总进「考核记录」 |
| 手动点「运行」 | 你自己在编辑器里点 | 只在调试脚本时用 |

webhook 配好之后，检查人在手机点提交 → 脚本立刻在金山服务器上执行。
检查人完全不需要知道「脚本」这回事，也不会忘 —— 忘了就等于没提交，页面会报错，不会静默丢数据。

定时任务在哪设：表格顶部「效率」→「高级开发」→「定时任务」→ 创建任务
→ 选「单次 / 每天 / 每周 / 每月」+ 时间 → 选中刚存的那个脚本。

> **定时任务只认 AirScript 脚本**，PY 脚本不在可选列表里。
> 所以「需要定时」的活儿必须写成 AirScript；`record_sync.py` 因为要跨工作簿读写，
> 仍然留在 PY 那一栏手动跑一次，一个月一次，不算负担。

## 还有一件必须做的事：让图片有权限显示

WPS 的 `=IMAGE()` 函数**每个文档第一次用要人工点一次授权**，没授权时格子显示 `#BLOCKED!`。

我拿三个不同域名的图片试过（百度 / wps.cn / GitHub Pages），三个都是 `#BLOCKED!`，
所以这不是图片地址的问题，是这个文档还没授权。

**做法**：用浏览器打开 `IMAGE函数验证.xlsx`（我建的测试表，在金山云盘根目录）。
如果格子旁边出现「授权 / 允许访问网络图片」之类的按钮，点一次，图片立刻出来 —— 然后对
`考核工作台数据源（V2.1）.xlsx` 和 `考核记录_2026.xlsx` 各点一次。

验证完这两个测试表可以直接删：`IMAGE函数验证.xlsx`、`IMAGE函数验证2.xlsx`。

如果打开后**根本没有授权提示、一直是 #BLOCKED!**，说明这个能力对你账号还没放开，
那就得换方案（图片改存链接，点了才能看）。这一步请务必先确认。

## 手机端：十几台手机，别让人人配一遍

> ✅ **2026-11-20 已定案：走中转，零配置上线。**
> 函数 URL 已填进 `docs/assets/config.js` 的 `report.url`，令牌只在函数环境变量里。
> 检查人打开打分页直接提交，什么都不用填。
> 下面「直连」那一节只作为应急备选保留（比如函数挂了临时顶一下），日常不用。

打分的是检查人，十余人各用自己手机。这决定了只能用哪一种接法：

| | 直连金山 | 走中转 |
|---|---|---|
| 每台手机要填什么 | webhook + **全账号级令牌** | 什么都不填 |
| 配几次 | 十几台各配一次 | 你配一次，写进 `config.js`，全员生效 |
| 某台手机丢了 | 那个令牌能读写你名下**全部**金山文档 | 最多被刷几次提交 |

跨域既然通了，直连就能用。要不要再套一层中转，只剩一个考量：**那串令牌要复制多少份。**

### 直连（应急备选，现已不用）

每位检查人**首次**提交时弹一次「一次性设置」，填 webhook + 令牌，之后不再问。

代价要认：AirScript-Token 是账号级凭据，能读写你名下**全部**金山文档。十几台手机
各存一份，就是十几个副本；任一台丢失或被翻看，等于交出整个账号。

三个能压低风险的做法：

1. 只发给固定的几位检查人，别转发到群里、别截图
2. 令牌默认 180 天到期，到期换新时所有人重填一次（也顺带作废旧令牌）
3. 万一手机丢了，立刻去金山删掉旧令牌重建 —— 旧的会立即失效

### 中转（可选，不是必装）

想彻底不给手机留凭据，就加 `tools/worker/relay.js`：令牌只留在中转端一处，
地址不含密钥、可以写进 `config.js`，检查人打开即提交、零配置。

```js
report: { url: 'https://kaohe-relay.你的账号.workers.dev' }   // token 留空
```

代码会自动识别：地址里带 `/api/v3/ide/` 就当直连、发令牌；不带就当走中转、不发。
两种模式可以随时切换，不用改别的地方。

## 跨域：已确认可以直连

我先用假地址模拟浏览器预检，得到 **403 且没有 `Access-Control-Allow-*` 头**，
据此判断「手机大概会被拦」，还专门写了个 Worker 兜底。

**真机实测推翻了它** —— 跨域是通的。那个 403 是「地址不存在」，不是跨域策略。

教训记在这：**拿假地址测出来的 403，不能当成跨域结论**；能判定的只有真 webhook。
以真机为准，Worker 从「必装件」降级为「备用件」。

`tools/worker/relay.js` 留在仓库里，不是必装。什么情况下才需要它：
以后换了浏览器内核、换了域名、或者金山改了网关策略，导致直连突然报跨域 ——
按它开头的注释部署一下就能救回来，不用改前端一行代码。

## 图片怎么进单元格

老思路是往格子写 `=IMAGE(公网直链)`，依赖两件事：图片有公网地址、文档对 IMAGE 外链做过授权。
第二条实测一直卡在 `#BLOCKED!`，这条路放弃。

改用 AirScript 的 **`Range.InsertImage(dataURL)`** —— 直接吃照片的 base64：

```js
const range = Range('N2')
range.InsertImage('data:image/jpeg;base64,/9j/4AAQ...')
```

| | 用 `=IMAGE()` | 用 `InsertImage()` |
|---|---|---|
| 图片要公网地址 | 要（得先传图床） | **不要** |
| 要文档授权 | 要，且卡在 `#BLOCKED!` | **不要** |
| 要多带一份 GitHub 令牌 | 要 | **不要** |
| 传输路径 | 手机→金山→GitHub→金山 | **手机→金山，直达** |
| 表格里是 | 公式，失败就是一串字 | 真图片，嵌在格子里 |

### 每个问题只放一张

N 列一格只能放一张图，插第二张会把第一张盖掉。所以：

- 打分页**每项只能拍 1 张**佐证照片（照片区就一个「拍照」+ 一个「从相册选」）
- 提交时每项只带这 1 张，插进对应行的 N 列
- 老草稿里如果还留着 3 张，提交时自动只取第 1 张，不会报错

脚本里有个 `PHOTO_MODE` 开关（`tools/airscript/score_write.js` 第 52 行）：

```js
PHOTO_MODE: 'cell',   // 'cell' = InsertImage 直传；'url' = 传图床 + =IMAGE
```

默认 `'cell'`。万一你的客户端版本没放开 InsertImage（脚本报
`InsertImage is not a function`），改成 `'url'` 就退回老路，不用改别的。

想提前验一下版本支持，把 `tools/airscript/_test_insertimage.js` 贴进编辑器跑一次，
看「检查明细」T1 格出不出红色小方块。

### 表格会长多大（已知代价，不是 bug）

图片是**存进表格文件本身**的，不是外链，所以表格会随月份累积变大。量级估算：

| 假设 | 数值 |
|---|---|
| 一个站一次检查的扣分项 | 约 10 项 → 10 张图 |
| 15 个站一个月 | 约 150 张 |
| 单张上限（当前设定） | **500KB** |
| 每月增量 | 约 45MB |
| 一年累计 | 约 540MB |

金山在线表格到几百 MB 会明显变卡。**这是 2026-11-19 明确接受的取舍**：
留 500KB 保证照片看得清，体积问题往后放。

什么时候该回头改：

- 表格打开明显变慢，或提示文件过大
- 一年下来超过 200MB

改法只动一个常量，不用改前端、不用重新部署：

```js
var PHOTO_MAX_BYTE = 500 * 1024;   // docs/assets/score.js，改成 150*1024 即 150KB
```

改完手机强制刷新一次（缓存版本号要跟着升），之后新拍的照片就是新上限；
已经进表的老图不会变小。

## 落表后长什么样

「检查明细」每次提交写这些列：

| 列 | 内容 |
|---|---|
| A 月份 / B 站名 / C 表类型 | 如 2026-11 / 韩城东 / 运营检查 |
| D 序号 / E 大类 / F 检查项目 | 只写被扣分的和判 NA 的项 |
| G 标准分 / H 得分 / I 结果 | 扣分得 0，NA 不进分母 |
| J 说明 | 手机里填的扣分原因（只写文字，不塞链接） |
| K 检查人 / L 提交时间 | 自动 |
| M 照片文件名 | 该项第 1 张的文件名；没拍照就留空 |
| **N 照片附件ID** | `InsertImage(照片数据)` —— 真图片嵌在格子里，不用图床、不用授权 |
| O 折算得分(100) / P 运营段得分(28) | 脚本当场算好 |
| Q 一票否决项 | 有就写，没有留空 |
| R 数据来源 / S 更新时间 | 手机直落表 / 提交时间 |

同站同月**重复提交以最新一次为准**（旧的整批删掉重写），不会叠加。

零扣分的满分站也会写一行占位（序号为空、说明「本项巡检未发现不符合项」），
否则 `record_sync.py` 会以为这站没检查过，整块留空白丢 28 分。

## 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点提交弹出「已发起下载 / 未安装可打开该链接的应用」 | 这台手机读到的 `config.js` 还是旧的（没提交地址），于是掉到打包下载那条旧路；安卓把 `blob:` 链接交给系统找应用，`.zip` 没人认领就报这句 | 按顺序试：① 完全关掉浏览器重开打分页；② 下拉刷新（`sw.js` 对 `config.js` 走网络优先，刷新一次就该更新）；③ 仍不行就清一次本站缓存；④ 最后检查这台手机有没有早先填过「一次性设置」——`localStorage` 会盖过 `config.js`，把它清掉 |
| 点「只导 Excel」出来的表里没有照片 | 正常。xlsx 文件本身装不了图，SheetJS 社区版也不支持嵌图 | 照片只有走直落表（`InsertImage`）才会进表；离线情况下先用微信单独发给科室 |
| 提交后提示「连不上 / 跨域」 | 网络抖动，或换了浏览器内核 | 换系统浏览器重试；先看金山表里是否其实已经有了，别重复提交。持续不行才启用 Worker |
| 表里行数对、照片列是 `#BLOCKED!` | 走的是 `=IMAGE()` 回退路线，文档没授权 | 见「让图片有权限显示」；改用 `InsertImage` 后不会再有这一条 |
| 提示「缺 items」 | 页面还是旧版缓存 | 手机上强制刷新一次（清 Service Worker） |
| 照片没上去，文字进去了 | GitHub 令牌失效或网络断 | 脚本日志里会写「照片上传失败 N 张」，重新提交即可 |
| 行写进去了但站名不对 | 只支持 30 个物理站名（华山南/华山北…） | 用物理站，不要用服务区名 |

## 这条链路的安全边界

| 模式 | 手机端带什么 | 泄露了会怎样 |
|---|---|---|
| **直连金山（默认）** | 脚本令牌（存本机 localStorage） | 别人能读写你名下**全部**金山文档 —— 全账号级凭据，这是直连的唯一代价 |
| Worker 中转（可选） | 什么都不带 | 最多被刷几次提交，不涉及凭据 |

`cell` 模式下照片不经图床，GitHub 令牌用不到 —— 它只在 `PHOTO_MODE='url'` 回退时才会被调用，
且只对 `kaohe-workbench` 一个仓库有写权限。哪天确定不再回退，把那行 `TOKEN` 删掉更干净。
