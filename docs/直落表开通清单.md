# 打分直落金山表 · 开通清单

一次性配置，配好之后**检查人**在手机上打分、拍照、点提交，扣分项和佐证照片直接进「检查明细」，
不需要打包、不需要下载、不需要发微信、也不需要开电脑。

> 角色分清：被打分的是油站，**打分并提交的是检查人**（计划经营科派出的考核人员，十余人）。
> 站长不参与提交，只在结果发布后确认得分。

---

## 你要在金山里做的 3 件事

### 1. 粘贴脚本

打开 **考核工作台数据源（V2.1）.xlsx** → 顶部「效率」→「高级开发」→「AirScript 脚本编辑器」→ 新建脚本
→ 把 `tools/airscript/score_write.js` 整个贴进去 → 保存（脚本名建议叫「打分直落表」）。

> 注意是 **AirScript 脚本编辑器（JS）**，不是右边的「PY 脚本」。
> `record_sync.py` 走 PY，这个走 JS，两个不是一处。

### 2. 建脚本令牌

同一个编辑器里，工具栏点「脚本令牌」→ 创建 → 复制那串字符。
（没做过实名认证会先让你认证一次。）

### 3. 复制 webhook 链接

脚本列表里找到刚存的「打分直落表」→ 右侧 `···` → 复制 webhook 链接。
长这样：

```
https://www.kdocs.cn/api/v3/ide/file/85jEfN5x.../script/V2-xxxx/sync_task
```

## 要不要每次都去点「运行」？不用

AirScript 脚本有三种跑法，这里只用第一种：

| 跑法 | 谁触发 | 用在哪 |
|---|---|---|
| **webhook（本方案用的）** | 手机点「确认提交」那一刻自动 POST | 打分直落表 |
| 定时任务 | 金山云端按你设的时间跑，不用开机、不用打开表格 | 每月把「检查明细」汇总进「考核记录」 |
| 手动点「运行」 | 你自己在编辑器里点 | 只在调试脚本时用 |

webhook 配好之后，检查人在手机点提交 → 脚本立刻在金山服务器上执行。
检查人完全不需要知道「脚本」这回事，也不会忘 —— 忘了就等于没提交，页面会报错，不会静默丢数据。

定时任务在哪设：表格顶部「效率」→「高级开发」→「定时任务」→ 创建任务
→ 选「单次 / 每天 / 每周 / 每月」+ 时间 → 选中刚存的那个脚本。

> **定时任务只认 AirScript 脚本**，PY 脚本不在可选列表里。
> 所以「需要定时」的活儿必须写成 AirScript；`record_sync.py` 因为要跨工作簿读写，
> 仍然留在 PY 那一栏手动跑一次，一个月一次，不算负担。

## 还有一件必须做的事：让图片有权限显示

WPS 的 `=IMAGE()` 函数**每个文档第一次用要人工点一次授权**，没授权时格子显示 `#BLOCKED!`。

我拿三个不同域名的图片试过（百度 / wps.cn / GitHub Pages），三个都是 `#BLOCKED!`，
所以这不是图片地址的问题，是这个文档还没授权。

**做法**：用浏览器打开 `IMAGE函数验证.xlsx`（我建的测试表，在金山云盘根目录）。
如果格子旁边出现「授权 / 允许访问网络图片」之类的按钮，点一次，图片立刻出来 —— 然后对
`考核工作台数据源（V2.1）.xlsx` 和 `考核记录_2026.xlsx` 各点一次。

验证完这两个测试表可以直接删：`IMAGE函数验证.xlsx`、`IMAGE函数验证2.xlsx`。

如果打开后**根本没有授权提示、一直是 #BLOCKED!**，说明这个能力对你账号还没放开，
那就得换方案（图片改存链接，点了才能看）。这一步请务必先确认。

## 手机端：十几台手机，别让人人配一遍

打分的是检查人，十余人各用自己手机。这决定了只能用哪一种接法：

| | 直连金山 | 走中转 |
|---|---|---|
| 每台手机要填什么 | webhook + **全账号级令牌** | 什么都不填 |
| 配几次 | 十几台各配一次 | 你配一次，写进 `config.js`，全员生效 |
| 某台手机丢了 | 那个令牌能读写你名下**全部**金山文档 | 最多被刷几次提交 |

所以：**直连只用来自己调试验证，正式发给检查人一律走中转。**

### 调试用（你一个人，临时）

打开打分页 → 打分 → 点「确认提交」→ 弹「一次性设置」→ 填 webhook 链接 + 脚本令牌。
只存这台手机（localStorage），不进网页源码。配好后每次提交都不再问。

### 正式用（十几位检查人，零配置）

中转部署完拿到地址后，改 `docs/assets/config.js`，加一段：

```js
report: { url: 'https://kaohe-relay.你的账号.workers.dev' }   // token 留空，它在中转端
```

推上线后，检查人打开打分页直接打分提交，**不会被问任何配置**。
地址里没有 `/api/v3/ide/`，代码就按中转处理，不发送令牌。

## 跨域：一个已实测的风险，和备用方案

直接对 `kdocs.cn` 的 sync_task 地址发了浏览器的跨域预检（OPTIONS + Origin 头），
返回 **403，且响应里没有任何 `Access-Control-Allow-*` 头**；换路径再试一次，结果一致。

这意味着 **手机网页直接 POST 到金山，很可能被浏览器拦掉**（请求根本发不出去）。
金山这套接口本来是给服务端调的 —— 官方示例清一色 curl / Java / Go / Python / Node，没有浏览器示例。

所以备了一个 40 行的中转：`tools/worker/relay.js`（Cloudflare Worker）。它做两件事：

1. 给浏览器回正确的 CORS 头，手机端不再被拦
2. 把 AirScript-Token 藏在服务端 —— 手机端一个凭据都不带

部署全程网页点选，不用命令行：

| 步 | 位置 | 做什么 |
|---|---|---|
| 1 | Cloudflare 控制台 → Workers & Pages | 新建 Worker，命名 `kaohe-relay` |
| 2 | Edit code | 把 `tools/worker/relay.js` 整体粘进去，Deploy |
| 3 | Settings → Variables and Secrets | 加两个 Secret：`KDOCS_URL`（webhook 链接）、`KDOCS_TOKEN`（脚本令牌） |
| 4 | 手机打分页「一次性设置」 | 提交地址填 Worker 地址，令牌**留空** |

免费额度每天 10 万次请求，15 个站用不完。

**顺序建议**：先按直连方式试一次，省一个组件；提示「连不上 / 跨域」再上 Worker。
打分页会自动识别 —— 地址里带 `/api/v3/ide/` 就当直连要令牌，否则当中转不带令牌。

## 落表后长什么样

「检查明细」每次提交写这些列：

| 列 | 内容 |
|---|---|
| A 月份 / B 站名 / C 表类型 | 如 2026-11 / 韩城东 / 运营检查 |
| D 序号 / E 大类 / F 检查项目 | 只写被扣分的和判 NA 的项 |
| G 标准分 / H 得分 / I 结果 | 扣分得 0，NA 不进分母 |
| J 说明 | 手机里填的扣分原因（只写文字，不塞链接） |
| K 检查人 / L 提交时间 | 自动 |
| M 照片文件名 | 全部佐证照片的文件名 |
| **N 照片附件ID** | `=IMAGE(直链)` —— 第 1 张直接出图；第 2、3 张的直链在下一个小节 |
| O 折算得分(100) / P 运营段得分(28) | 脚本当场算好 |
| Q 一票否决项 | 有就写，没有留空 |
| R 数据来源 / S 更新时间 | 手机直落表 / 提交时间 |

同站同月**重复提交以最新一次为准**（旧的整批删掉重写），不会叠加。

零扣分的满分站也会写一行占位（序号为空、说明「本项巡检未发现不符合项」），
否则 `record_sync.py` 会以为这站没检查过，整块留空白丢 28 分。

## 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提交后提示「连不上 / 跨域」 | 浏览器拦了金山域名的跨域响应（已实测确认金山不返回 CORS 头） | 上 Worker 中转，见上面「跨域」一节；先看金山表里是否其实已经有了，别重复提交 |
| 表里行数对、照片列是 `#BLOCKED!` | 文档没授权 IMAGE | 见上面「让图片有权限显示」 |
| 提示「缺 items」 | 页面还是旧版缓存 | 手机上强制刷新一次（清 Service Worker） |
| 照片没上去，文字进去了 | GitHub 令牌失效或网络断 | 脚本日志里会写「照片上传失败 N 张」，重新提交即可 |
| 行写进去了但站名不对 | 只支持 30 个物理站名（华山南/华山北…） | 用物理站，不要用服务区名 |

## 这条链路的安全边界

| 模式 | 手机端带什么 | 泄露了会怎样 |
|---|---|---|
| 直连金山 | 脚本令牌（存本机 localStorage） | 别人能读写你名下**全部**金山文档 —— 这是全账号级凭据 |
| **Worker 中转（推荐）** | 什么都不带 | 最多被刷几次提交，不涉及凭据 |

GitHub 令牌始终只在金山脚本里，且只对 `kaohe-workbench` 一个仓库有写权限。
